# DataGrid JIT and NativeAOT acceptance

This console tests the maintained DataGrid project directly. It deliberately does not reference or start the application. The application collection helper is linked from its real source file. The eight production grid configurations use inert package, history, shortcut, catalog and TUI display models with compiled XAML, the application's comparer logic and a record-only command implementation.

Run from the repository root:

```powershell
./scripts/verify-datagrid-provenance.ps1
./scripts/verify-datagrid-aot.ps1 -OutputDirectory <fresh-evidence-directory> -RuntimeIdentifier win-x64
```

This is an executable acceptance suite, not a VSTest assembly: `dotnet test` does not execute it. The script runs `boundaries` and `ui` in separate processes in JIT and NativeAOT, checks their exits and assertions, compares corresponding results and retains logs and hashes. Native commands require `--expect-aot`; a JIT fallback fails the runtime assertion.

The boundary suite has 38 assertions covering explicit/compiled template columns, empty and populated sources, notifications, sorting, checkbox binding, selection, item factories, typed grouping and explicit rejection of unsupported reflection requests. The UI suite defines 1,102 assertions across eight grid configurations and their comparer contracts (320 original desktop checks, 107 Catalog checks and 641 TUI checks, plus 34 incremental-update/move checks), including numeric download-size ordering and unknown sizes remaining last in both menu-sort directions. Each grid starts empty, displays its first added row with the expected identity and compiled binding, and later clears a selected row and repopulates. Coverage also includes 400-row virtualization, sorting and null/equal/nested values, source changes and column visibility/resize/reorder.

Keyboard checks verify exact Down/Up row selection, Home/End column movement, configured command modifier + Home/End row and column endpoints, page movement and endpoint clamping, retained current column and grid focus. Large-page expectations use the visible rows presenter's height and the fixture's fixed row height. Tab and Shift+Tab verify specific template control focus and unchanged selection before any sorting/recycling; visual traversal order after row recycling is not assumed to equal collection order. Pointer/Space checkbox changes, two-way model binding and inert commands remain covered after sorting. The actual template columns reject edit transactions; this suite does not invent editable text cells for these read-only columns. Changes to copied comparer/version regions must be reflected in the fixture and pass the source-drift check.

Each command initializes Avalonia once with headless drawing. Avalonia 12.0.4's headless backend defaults to Control for the command modifier on every host; the native macOS hotkey configuration is not selected by this fixture. This verifies control state and input behavior, not rendered pixels, operating-system accessibility, real package operations, network services, user databases or installed shortcuts. The Windows CI job establishes win-x64 acceptance; the other release architectures require their own compatible host/toolchain and runtime checks.

The Catalog fixture retains the five production template columns and parent install-command binding with an inert recording command. It checks first-row metadata, the actual sorting callbacks and arrow updates, status/enable/opacity bindings, memory-only icon/fallback transitions, read-only editing, input, refresh and recycling. The small icon scaffold uses an in-memory bitmap and text fallback rather than the production SVG resource.

The three TUI configurations link the real typed list and explicit text-binding helpers. Package columns are tested in all four page variants with optional columns off/on; History and Operations exercise actual header clicks with independently specified row order per field. The extracted package handler records sort requests; package-engine sorting, persisted settings and page refresh identity are covered separately by the actual TUI test project. The TUI headless fixtures cover small list replacement and selection, not large-data recycling or terminal-host rendering. See `Ui/TuiGrids/production-extracts.json` and its read-only verifier for exact production fragments and helper hashes. The acceptance receipt records these inputs and the imported fixture manifest for every JIT/native scenario.

The incremental package fixture uses the exact production update/order methods with inert rows. It checks delayed download-size and checkbox sort changes, reference-stable equal insertion, and a scrolled 400-row DataGrid through additions, removals and moves. Assertions compare the actual collection view and rendered cells, retain selected/current identities while moving a selected row in both directions across the viewport, and verify a stable untouched scroll anchor. Single-item moves in plain views remain incremental. Filtered, sorted, grouped, paged or range moves use the collection view's explicit refresh fallback; this suite tests filtered, sorted and range correctness and does not claim no-Reset behavior for transformed views.
